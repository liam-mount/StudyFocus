# Approved implementation contract
Astra owns architecture/scaffolding and core/native/Chrome/security. Delegated UI code uses src/api.js and shared/contracts.d.ts only. Screens receive a `state` snapshot and `onError(message)` callback; use api commands, which return updated snapshots (desktop-only commands return status objects). App subscribes to authoritative snapshots. Never mutate a session in the renderer. Simulated mode is test-only and clearly labeled. Backend rejects missing/inactive targets, invalid durations, concurrent starts, schedule overlaps, and unsafe identities.

UI structure owned by Astra: App.jsx shell, sidebar, global snapshot/subscription, onboarding and CSS integration. Routine workers own assigned view/component files only, no architecture changes. Style: warm neutral/light/dark, blue action, compact sidebar, few cards, generous spacing, lucide-react icons, keyboard-accessible forms and confirmation dialogs, no emoji decoration. Main nav Focus / Profiles / Schedule / History; Settings at bottom. UI APIs defined in src/api.js. Engine start input uses apps, sites, mode/workMin/breakMin/rounds, optional profileId/label. Profile adds id/name/color. Schedule adds id/profileId/days 0=Sun..6=Sat/time HH:mm/enabled. Completed actions update state via subscription. api.emergency() is only called after explicit UI confirmation. All commands reject with readable Error.message.
